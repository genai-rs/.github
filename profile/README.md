# GenAI-RS

Rust libraries for the OpenAI API and for Langfuse observability.

## Choose a starting point

- **Call OpenAI (or an OpenAI-compatible API):** start with [openai-ergonomic](https://github.com/genai-rs/openai-ergonomic): builders, streaming, interceptors (including Langfuse/OpenTelemetry), a tool framework, provider presets (OpenAI, Azure OpenAI, OpenRouter, Groq, Ollama or a custom endpoint), pluggable authentication (`AuthProvider`), webhook verification, large-file uploads and WebAssembly support. Use [openai-client-base](https://github.com/genai-rs/openai-client-base) when you want the generated API surface directly or are building your own abstraction.
- **Use the Langfuse API:** choose [langfuse-ergonomic](https://github.com/genai-rs/langfuse-ergonomic) for builders, batching (also on WebAssembly), prompts, datasets and scores, against Langfuse v3 or v4 servers. Use [langfuse-client-base](https://github.com/genai-rs/langfuse-client-base) for the generated bindings.
- **Export OpenTelemetry spans to Langfuse:** choose [opentelemetry-langfuse](https://github.com/genai-rs/opentelemetry-langfuse). It configures the OTLP exporter and Langfuse context and needs no Langfuse API client at runtime. Use the same OpenTelemetry release family as the exporter (see its `Cargo.toml`).

## How the pieces fit

- **Generated base clients.** `openai-client-base` and `langfuse-client-base` are generated from the upstream OpenAPI specifications by the `timvw-rust` generator. Nothing is patched after generation: crate-specific choices are generator options (`langfuse-client-base` also applies documented legacy v3 compatibility data to its input spec), and fixes to generated code go into the generator. Requests go through [`timvw-rust-runtime`](https://docs.rs/timvw-rust-runtime), a tower-based HTTP stack (reqwest by default) with retries and backoff that honour `Retry-After`, providers via `ProviderLayer`, per-call `RequestOptions`, streamed uploads and downloads, typed server-sent event streams and WebAssembly support. Credentials are `SecretString`s. `openai-client-base` exposes a Cargo feature per API group (named after async-openai's, each with a `-types` twin that compiles only the models).
- **Handwritten ergonomic layers.** `openai-ergonomic` and `langfuse-ergonomic` add builders, orchestration and configuration on top of their base client and track its latest release; the API models come from the generated crates.
- **OpenTelemetry.** `opentelemetry-langfuse` builds on [OpenTelemetry Rust](https://github.com/open-telemetry/opentelemetry-rust). `openai-ergonomic`'s optional OpenTelemetry/Langfuse support currently uses the same OpenTelemetry release family, so their SDK types interoperate; OpenTelemetry types from different release families do not. Check the crates' `Cargo.toml` when upgrading.

## Shared CI

[genai-rs/.github](https://github.com/genai-rs/.github) holds the shared configuration: reusable CI and security workflows, a canonical `deny.toml` and a Renovate preset. A gate job skips the heavy CI jobs for a pull request whose commit carries a `local-ci` attestation from [`scripts/local-ci.sh`](https://github.com/genai-rs/.github/blob/main/scripts/local-ci.sh), and an optional `wasm` job builds and tests for `wasm32-unknown-unknown`. See its [README](https://github.com/genai-rs/.github#readme).

## Contributing

Report bugs, suggest improvements, or submit focused changes in the relevant repository. Read that repository's contribution guidance and `AGENTS.md` when present. Do not edit generated code by hand: fix the generator or its configuration instead.
